Flask 기록은 공통 항목으로 바꾸었다. 그런데 같은 요청을 남긴 Nginx 기록은 긴 글 한 줄이라 그대로는 같은 이름으로 읽을 수 없다. 이번 목표는 Nginx 원문에서 요청·상태·시각을 꺼내 Flask와 같은 항목으로 돌려주는 것이다. 원본 한 줄이 출처와 원문을 보존한 공통 기록 한 건으로 바뀐다. 원본에 실제로 있는 시각만 읽는다.

2단계. 큰따옴표를 기준으로 요청 부분 꺼내기

Flask 기록처럼 항목 이름으로 바로 찾을 수 없으므로, 이 Nginx 형식에서 각 값의 자리를 먼저 나눈다. split은 지정한 글자를 경계로 문자열을 나누는 기능이다. 문법을 읽는 작은 예 — 저장하지 않는다

text = "왼쪽|가운데|오른쪽"

['왼쪽', '가운데', '오른쪽']

3단계. 상태는 숫자로, 시각은 같은 기준으로 맞추기

요청 부분을 공백으로 나누면 방법·경로·버전 세 값이 나온다. 상태 문자열은 int로 정수로 바꾼다. 이렇게 해야 Flask의 숫자 200과 Nginx의 상태도 같은 방식으로 비교할 수 있다. 시각도 표기가 다를 수 있다. UTC(Coordinated Universal Time)는 시각을 비교할 때 사용하는 공통 기준이다. 원문의 +0900은 UTC보다 9시간 앞선 표기이므로 14시 36분 07초는 같은 순간의 UTC 05시 36분 07초로 표현된다. 시각 자체를 새로 만드는 일이 아니다. datetime은 Python에 포함된 날짜·시각 처리 도구다. datetime.strptime는 지정한 모양대로 시각 글자를 읽고, astimezone(timezone.utc)는 같은 순간을 UTC로 표현한다. isoformat()은 그 값을 연-월-일과 시각이 포함된 문자열로 만든다.

원문 예시 읽는 모양
14/Oct/2026 %d/%b/%Y: 일·영문 월 이름·연도
14:36:07 %H:%M:%S: 시·분·초
+0900 %z: UTC와의 차이

각 값이 만들어지는지 확인하기

  1. lesson3.py를 아래 전체 코드로 바꾸고 Ctrl+S로 저장한다.
  2. 실행한 뒤 요청 값과 원본·공통 시각을 나란히 읽는다.

from datetime import datetime, timezone
from learning.classroom_data import read_case

line = case["nginx"][0]
prefix, request_text, suffix = line.split('"', 2)
method, path, protocol = request_text.split()

time_text = prefix.split("[", 1)[1].split("]", 1)[0]
parsed_time = datetime.strptime(time_text, "%d/%b/%Y:%H:%M:%S %z")
common_time = parsed_time.astimezone(timezone.utc).isoformat()

print("요청", method, path, status_code)
print("상태가 숫자인가", isinstance(status_code, int))
print("원본 시각", time_text)

4단계. 공통 기록을 돌려주는 함수 완성하기

값을 꺼내는 처리를 확인했으니 Flask와 같은 항목을 반환하도록 묶자. 입력만 Nginx 문자열이고, 반환할 이름은 id, source, time, method, path, status_code, raw로 같다. 정규화 함수 저장하기

  1. 같은 learning 폴더에 normalize_nginx.py를 만들거나 연다.
  2. 아래 전체 코드를 넣고 Ctrl+S로 저장한다. 날짜 처리 도구는 Python에 포함되어 있어 새 패키지를 설치하지 않는다.

normalize_nginx.py — 파일 전체

from datetime import datetime, timezone


def normalize_nginx(line, number):
    prefix, request_text, suffix = line.split('"', 2)
    method, path, protocol = request_text.split()
    time_text = prefix.split("[", 1)[1].split("]", 1)[0]
    parsed_time = datetime.strptime(time_text, "%d/%b/%Y:%H:%M:%S %z")
    return {
        "id": f"nginx-{number}",
        "source": "nginx",
        "time": parsed_time.astimezone(timezone.utc).isoformat(),
        "method": method,
        "path": path,
        "status_code": int(suffix.split()[0]),
        "raw": line,
    }

함수 앞부분은 방금 실행한 분리·시각 해석 코드다. 반환 딕셔너리에서 출처는 nginx, 이름은 nginx-1처럼 이 파일 안의 순서로 붙인다. raw에는 원본 문자열을 그대로 넣어 어떤 글자를 해석했는지 다시 볼 수 있게 한다. 같은 함수로 두 줄 처리하기

  1. lesson3.py를 아래 전체 코드로 바꿔 저장한다.
  2. 같은 폴더에 normalize_nginx.py와 준비된 classroom_data.py가 있는지 확인한 뒤 실행한다.

lesson3.py — 이번 시간이 끝날 때 남길 전체 파일

from learning.classroom_data import read_case
from learning.normalize_nginx import normalize_nginx

case = read_case()
for number, line in enumerate(case["nginx"], start=1):
    event = normalize_nginx(line, number)
    print(event["id"], event["source"], event["method"],
          event["path"], event["status_code"])
    print("원본 보존", event["raw"] == line)
    print("UTC 시각", event["time"])

프로젝트 폴더의 Windows CMD

docker compose -f compose-monitor.yaml exec monitor-api python -m learning.lesson3

enumerate(..., start=1)이 원문과 순서를 하나씩 주고, normalize_nginx가 한 건을 바꾼다. event["raw"] == line은 반환값에 같은 원문을 남겼는지 확인한다. print 세 개가 요청·원본 보존 여부·시각을 차례로 보여 준다.

  • Nginx 두 결과의 항목 이름이 Flask 결과와 같다.
  • status_code는 숫자이고 raw에는 원본 문자열이 남는다.
  • Nginx 시각은 원문에서 바꾸어 표현하고 Flask의 없는 시각은 여전히 None으로 둔다.

확인문제

확인문제 1. 이번 입력은 Flask 딕셔너리와 어떻게 다른가?

정답과 해설

Nginx가 남긴 문자열 한 줄이다. 이름으로 바로 값을 읽기보다 큰따옴표·공백·대괄호 위치를 이용해 항목을 꺼낸다.

확인문제 2. line.split('"', 2)에서 2는 결과 두 개라는 뜻인가?

정답과 해설

아니다. 최대 두 번 나눈다는 뜻으로 앞부분·요청 부분·뒷부분 세 개가 생긴다.

확인문제 3. 첫 큰따옴표 안의 요청 부분에는 어떤 값이 있는가?

정답과 해설

요청 방법, 경로, HTTP 버전이다. GET / HTTP/1.1에서는 GET·/·HTTP/1.1 세 값이다.

확인문제 4. 큰따옴표 뒤에서 상태를 꺼내는 코드는 무엇인가?

정답과 해설

suffix.split()[0]이다. 뒤쪽을 공백으로 나눈 뒤 첫 값인 상태 문자열을 꺼낸다.

확인문제 5. 화면에 200으로 보이는 상태를 왜 int로 바꾸는가?

정답과 해설

원문에서 나눈 값은 문자열이기 때문이다. 숫자 상태를 가진 Flask 결과와 같은 조건으로 비교하려면 정수로 맞춘다.

확인문제 6. 입력 번호를 2로 바꾸면 왜 없는 경로가 나오는가?

정답과 해설

같은 파일의 두 번째 Nginx 원문이 그 요청을 기록했기 때문이다. 변환 코드가 새 요청이나 오류를 만든 것이 아니다.

확인문제 7. 원문 14시 36분 07초 +0900을 UTC 05시 36분 07초로 바꾸면 사건 시각이 달라지는가?

정답과 해설

아니다. 같은 순간을 다른 시간대 기준으로 표현한다. 원문의 시간대 차이를 함께 읽기 때문에 가능한 변환이다.

확인문제 8. Nginx에 시각이 있으니 Flask의 time도 그 값으로 채워도 되는가?

정답과 해설

안 된다. Flask 원본에는 시각이 없으므로 None을 유지한다. 출처가 다른 값을 확인 없이 원본 사실로 채우지 않는다.

확인문제 9. raw에 원문 전체를 남기는 이유는 무엇인가?

정답과 해설

공통 항목이 어떤 원문에서 나왔는지 확인하고, 변환하지 않은 항목도 다시 살펴보기 위해서다.

확인문제 10. 두 결과의 공통 항목이 같아지면 다음에 무엇을 할 수 있는가?

정답과 해설

한 목록으로 모아 같은 열과 조건으로 읽을 수 있다. 출처와 원문은 유지하며, 행을 합친 것만으로 같은 요청임을 증명하거나 중복 제거한 것은 아니다.

입력이 객체이든 문자열이든 같은 항목의 기록을 반환하게 만들었다. 다음에는 두 함수의 결과를 한 목록에 모아 함께 읽어 보자.
